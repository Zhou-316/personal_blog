# 个人博客液态玻璃 UI 改版方案

日期：2026-10-23（北京时间）

阶段：方案已生成，尚未实施 UI 改动、启动预览或完成验收。

本轮目标：以现有博客为基础完成液态玻璃 UI 改版，先在本机独立端口运行，由用户验收后再安排上线。

## 1. 改版目标与范围

视觉方向：**雪山背景、冷色玻璃、清晰文字、克制的动态反馈**。

沿用“海边的西西弗斯”的站点身份、雪山背景、四个站主栏目与灌水区。通过统一透明度、边缘高光、折射、阴影与间距，让界面从当前的磨砂玻璃进一步呈现液态玻璃质感。

第一轮覆盖首页、分类页、灌水区、文章阅读页、写作页、个人中心和登录注册弹窗。保留现有搜索、文章、评论、点赞、AI 总结、图片上传、通知和私信功能；本轮不新增找回密码、第三方登录等业务功能，也不重写后端。

交付重点：

1. 首页和导航建立完整的视觉基准，先提供本地可操作版本。
2. 同一套玻璃样式与交互规则覆盖其余页面。
3. 在 Chrome / Edge、手机布局和兼容模式下完成验证。
4. 本地验收通过后，再把本轮 UI 改动按用户授权提交、推送到 main；生产部署作为后续独立步骤。

## 3. 视觉与交互设计

### 3.1 页面层次

从背景到前景依次为：雪山照片 → 保证文字对比度的背景蒙层 → 玻璃容器 → 清晰的内容与操作。

| 区域 | 设计安排 |
| --- | --- |
| 顶部导航 | 桌面端采用有留白的悬浮玻璃栏，吸顶；保留品牌、搜索和现有操作。页面滚动时可观察背景穿过玻璃边缘 |
| 搜索框 | 轻磨砂输入区；焦点边框清楚。搜索结果独立浮层，超出导航边界时不被裁切 |
| 首页首屏 | 保留“云山苍苍，江水泱泱”及站点介绍；收敛装饰，让标题、操作和统计形成清楚的主次关系 |
| 首屏按钮 | “写札记”保持最高操作优先级；“最新一篇”等次级按钮呈现更明显的玻璃折射和轻微按压反馈 |
| 四个站主栏目与灌水区 | 保持现有内容关系；统一卡片边框、间距、标题与摘要层级。桌面端多列，手机端单列 |
| 侧栏 | 与主内容对齐，采用更轻的玻璃底色；窄屏下置于主内容之后 |
| 文章阅读页 | 外层保留玻璃材质，正文使用较实的浅色底；代码块、表格、图片和引用保持可辨识 |
| 写作页 | 编辑区优先保证光标、选区和文字清晰；预览区与工具区使用同一套容器样式 |
| 个人中心与消息 | 统一页头、标签、未读标记、列表和对话气泡；消息输入框不随玻璃弹性移动 |
| 登录注册弹窗 | 玻璃外壳与较实的表单底色；清晰的关闭、错误、加载与焦点状态 |

### 3.2 玻璃强度

| 层级 | 使用位置 | 表现 |
| --- | --- | --- |
| 强调玻璃 | 导航、少量首屏按钮 | 背景折射、细边高光、轻微色散；弹性只用于少量独立控件 |
| 常规玻璃 | 栏目卡片、侧栏、弹窗外壳 | 磨砂、柔和阴影、细边高光；默认不启用鼠标形变 |
| 阅读底板 | 正文、编辑器、长列表、聊天内容 | 较高底色不透明度，减少背景干扰 |

导航、搜索和多列表单保持布局稳定。长文章卡片及消息列表不逐项运行鼠标跟踪和复杂 SVG 滤镜。

### 3.3 建议样式参数

以下是第一版起始值，以真实页面预览结果为准：

| 参数 | 初始安排 |
| --- | --- |
| 主文字 | 深蓝灰，例如 #203344 |
| 强调色 | 低饱和蓝绿，例如 #386f82 |
| 玻璃底色 | 白色叠加，强调区约 18%–35%、卡片约 55%–75%、阅读区约 92%–97% 不透明度 |
| 背景模糊 | 常规玻璃约 12–20px，避免多层大面积叠加 |
| 圆角 | 容器约 20–28px、输入框约 12–16px、独立按钮可使用胶囊形 |
| 间距 | 使用 4 / 8 / 12 / 16 / 24 / 32 / 48px 的一致步长 |
| 交互时长 | 约 160–220ms；悬停位移不超过 2px |
| 阅读宽度 | 正文约 720–800px 上限，根据实际布局调整 |

正文默认深色，首屏标题可在有足够深色蒙层的位置使用白色。颜色与透明度一起验证，普通正文对比度目标不低于 4.5:1。

## 4. 技术实施

### 4.1 组件库使用方式

采用 liquid-glass-react。已读源码中的依赖声明支持 React >=18；安装时核对实际发布版本与导出类型，并将所选版本写入锁文件。默认使用 standard 模式，第一轮不采用官方说明中稳定性较弱的 shader 模式。

先封装项目内组件，再接入页面：

| 拟新增文件 | 职责 |
| --- | --- |
| frontend/src/components/glass/GlassSurface.tsx | 统一玻璃容器与兼容样式，按场景选择 CSS 或组件库效果 |
| frontend/src/components/glass/GlassButton.tsx | 保留原生 button 的键盘、焦点、disabled 和表单语义；接入轻微动态反馈 |
| frontend/src/styles/glass.css | 玻璃配色、透明度、边框、阴影、组件库适配与兼容规则 |
| frontend/src/hooks/useGlassCapabilities.ts | 在实施需要时提供动效偏好、指针类型与兼容策略，不以浏览器名称作为唯一判断依据 |

组件名称与文件拆分可随实现微调。封装重点解决已在源码中看到的集成问题：

- 默认居中位移和多层装饰元素需要适配普通文档流，不能直接包住现有布局后就视为接入完成。
- 内部部分 class 使用 utility 命名；补齐实际需要的局部样式，并限定作用域，避免影响全站。
- 内部内容字体、行高和阴影有默认值，需要恢复为博客自身的排版规范。
- 大小测量主要发生在挂载和窗口变化时；异步内容、长标题和弹窗尺寸变化后，要验证高光边框仍与容器对齐。必要时在封装中补充尺寸适配。
- 容器带 onClick 不等于原生按钮；交互控件必须保留真实 button 元素和正确的焦点顺序，避免嵌套按钮。
- 搜索浮层和弹窗放在适合的层级，避免受玻璃层的 overflow、transform 或层叠上下文影响。

起始调参范围：displacementScale 约 24–48、aberrationIntensity 约 0.5–1、独立按钮 elasticity 约 0.04–0.10，导航与表单为 0。blurAmount 是组件参数，不是直接的像素值，按实际画面调整。

### 4.2 兼容、动效与性能

- Chrome / Edge 验证完整折射效果；Safari / Firefox 验证官方说明中的部分效果及兼容样式。
- 不支持所需效果时，使用 CSS 半透明底色、模糊、边框与阴影；不支持模糊时提高底色不透明度。
- CSS.supports 的语法检测不能保证视觉折射正确，仍需实际浏览器检查；提供便于验收的简化玻璃开关。
- prefers-reduced-motion 或粗指针设备关闭鼠标弹性、连续跟随及非必要的入场动画；减少动态效果时，首屏标题直接完整显示。
- 第一版优先把复杂折射控制在导航和少量首屏控件中，再根据实际性能决定是否扩展。
- 同一台机器、同一浏览器和同一视口对比改造前后的滚动、输入与交互记录；不在缺少设备信息时承诺固定帧率。

### 4.3 改动边界

主要修改 frontend/src/App.tsx、frontend/src/styles.css 及必要的新增展示组件，并更新依赖与本地验收配置。整理此次触及的重复 CSS，不同时重写整站状态管理。

后端仅在验收确实受阻时处理必要的本地接入问题。例如当前上传接口返回 /uploads/ 路径，而 app.main 尚未挂载该静态目录，需要在实施时验证；若本地图片确实无法回显，再以受控的静态目录挂载修复。此类修复单独说明和验证。

## 5. 本地验收环境

### 5.1 端口与隔离

生成方案时已检查以下候选端口：5173、5174、4173、4174、8000、8001，均未发现 TCP 监听。端口状态会变化，实际启动前重新检查。

| 用途 | 默认地址 | 安排 |
| --- | --- | --- |
| 开发验收前端 | http://127.0.0.1:5174 | Vite，绑定本机，开启 strictPort |
| 验收后端 | http://127.0.0.1:8001 | 独立 FastAPI 进程 |
| 后端健康检查 | http://127.0.0.1:8001/api/health | 确认返回正常状态后再验收页面 |
| 构建产物复核 | http://127.0.0.1:4174 | 验收后期使用 Vite preview，配置相同代理 |

端口被占用时重新选择空闲端口，并同步更新前端代理、允许来源和验收地址；不终止未知进程，不依赖 Vite 静默切换端口。

验收数据库与上传文件放入项目 .dist/local-acceptance/ 下，使用单独的 SQLite 文件和 uploads 目录，复用现有 .dist 忽略规则。准备测试站主和普通用户、四类文章、灌水帖、评论、通知与私信，仅使用本地测试数据。

### 5.2 接口配置

当前 frontend/.env.development 指向 http://127.0.0.1:8000/api；后端默认 CORS 只允许 5173。因此不能仅更换前端端口就开始验收。

拟提供项目根目录下的 start-local-acceptance.ps1，统一完成端口检查、运行目录准备和启动配置，并返回明确的访问地址及停止方式。通过当前进程环境变量覆盖 API 地址，不改动用于其他用途的环境文件。

前端启动约定：

```powershell
# 在 frontend 目录运行；需要先实施对应的 Vite 代理配置。
$env:VITE_API_BASE_URL = '/api'
$env:BLOG_DEV_API_TARGET = 'http://127.0.0.1:8001'
npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

Vite 开发服务器与 preview 均配置 /api、/uploads 代理，目标读取 BLOG_DEV_API_TARGET。/api 前缀保持不变，与后端路由一致。图片代理还需后端实际提供对应的静态文件。

后端启动约定：

```powershell
# 在 backend 目录运行。
$env:PYTHONPATH = '.python_packages'
$env:BLOG_DATABASE_PATH = Join-Path $PWD '..\.dist\local-acceptance\blog.db'
$env:BLOG_UPLOADS_DIR = Join-Path $PWD '..\.dist\local-acceptance\uploads'
$env:CORS_ORIGINS = 'http://127.0.0.1:5174,http://127.0.0.1:4174'
python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

实施时核实本地依赖，尤其是上传接口所需的 multipart 支持；缺少时补齐可复现的依赖声明。验收期间浏览器请求均指向本地接口。

以上命令描述实施后的运行方式，尚未创建启动脚本、修改代理配置或启动服务。
