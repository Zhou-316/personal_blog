# 液态玻璃第二轮方案：扩大覆盖范围，建立清楚的材质差异

日期：2026-10-24（北京时间）。

状态：实施方案；参数为待验证的候选值。本次只生成方案，不修改现有界面，不重启已经运行的 http://127.0.0.1:5175 服务。

## 1. 目标与判断标准

这一轮要让读者在打开首页、移动鼠标、滚动页面和切换栏目时，都能感受到玻璃的通透、厚度与光线变化。两种模式的区别应在第一屏就能辨认，阅读正文时则保持安静。

最终效果应满足四个条件：

1. **静止也能看出区别。** 不需要先找到导航边缘，首页首屏、栏目容器和侧栏就能呈现清楚的材质变化。
2. **交互时能感到“液态”。** 移动鼠标时高光顺着边缘变化；滚动时，玻璃下方的纹理在边缘发生折射；点击独立控件时有短促、轻微的按压反馈。
3. **全站有一致的材料层次。** 导航、栏目、分类、个人中心、弹窗和配乐控件都参与模式切换，同时有明确的强弱关系。
4. **读字和操作保持稳定。** 正文、代码、编辑输入和聊天内容不被扭曲，点击目标不随装饰层漂移。

“最佳值”指在本博客的背景、排版和参考设备上，兼顾可辨识度、美感、阅读与性能的参数组合。它需要逐轮比较，不等于把所有强度调到最大，也不代表所有设备上的数学最优解。

## 2. 当前效果为什么偏弱

根据现有代码及 5175 页面此前的浏览器对比：

| 项目 | 当前情况 | 带来的结果 |
| --- | --- | --- |
| 覆盖范围 | 只有顶部导航渲染一个复杂折射层 | 页面主体没有跟着模式变化 |
| 导航底色 | 白色渐变约 76% → 50% 不透明度，两种模式相同 | 大量背景信息被遮住，主要剩下边框差异 |
| 栏目与侧栏 | 两种模式共用约 82% → 61% 的底色、16px 模糊 | 首屏下方始终是同一种磨砂材质 |
| 鼠标交互 | elasticity 为 0，鼠标坐标固定为 0 | 没有随鼠标移动的方向高光和弹性反馈 |
| 背景层 | 下方蒙层较厚，部分区域接近纯浅色 | 即使增加折射参数，也可能缺少可观察的背景纹理 |
| 装饰边缘 | 库自带的多层明暗边框比较突出 | 容易呈现厚灰框，削弱轻盈、清透的观感 |

因此，这一轮同时处理覆盖范围、材料结构、背景取样和交互，不仅调整 displacementScale。

## 3. 材料分层

采用“背景纹理 → 玻璃材质 → 局部读字底色 → 清晰内容”的结构。降低的是装饰材质的遮挡，文字所在区域按需要保留承托底色。

| 层级 | 作用 | 本轮安排 |
| --- | --- | --- |
| 背景 | 给玻璃提供可见的颜色与纹理 | 保留雪山照片；减轻过厚的全局白色蒙层，亮部与暗部都参与测试 |
| 玻璃外层 | 表现通透、厚度、折射与光线 | 用较透明的底色、边缘高光和少量阴影建立材质 |
| 读字底层 | 稳定文字对比度 | 在卡片内侧、搜索输入、正文和表单下方按场景加浅色或深色衬底 |
| 内容与操作 | 保证清晰、可选中、可点击 | 文字、图标、输入控件保持独立；不对正文整体应用光学滤镜 |

Apple 的材料指南把 Liquid Glass 用于导航与控制层，并建议内容层采用标准材质。本博客据此让全站容器拥有统一的玻璃外观，把明显的动态折射集中在功能控件上。[设计依据](https://developer.apple.com/design/human-interface-guidelines/materials)

### 3.1 三种材料角色

- **展示玻璃：** 导航、首屏玻璃边缘、独立操作按钮。承担最明显的通透和光线反馈。
- **内容玻璃：** 栏目、分类卡片、侧栏、个人中心容器。静止时就有透景与厚度，悬停时主要改变边缘；长列表不逐项持续形变。
- **阅读底板：** 正文、代码、编辑器和聊天文字。保留较实的读字区域，外框、工具栏和操作控件呈现玻璃材质。

全局背景的调整同时应用于两种模式，比较时使用相同照片与背景蒙层，保证差异来自材质本身。

## 4. 具体调整范围

强度分为“明显、中等、轻微”，指视觉目标，不表示每个区域都运行同一种滤镜。

| 区域与现有入口 | 液态模式调整 | 强度与动态 | 简化模式 |

不恢复此前移除的首屏统计、“最新一篇”或右上角“写札记”。保留 GitHub 位于个人中心左侧的排列，不更改现有发帖、配乐和通知业务。

## 5. 两种模式必须有明确区别

| 观察点 | 液态玻璃 | 简化玻璃 |
| --- | --- | --- |
| 静态首页 | 导航、首屏、栏目与侧栏的外围都有透景和光学厚度 | 相同布局下，材质更厚、更均匀 |
| 背景经过边缘 | 完整效果环境中能看见局部折射 | 模糊过渡，无复杂位移 |
| 鼠标移动 | 当前交互区域有方向高光 | 固定光线 |
| 独立按钮按压 | 有短促的光线收束与轻微弹性 | 保留简单按压状态 |
| 标签切换 | 选中指示层有玻璃感和短过渡 | 稳定选中底色 |
| 长文章阅读 | 玻璃感主要留在外围和工具 | 保留清晰的阅读界面 |

两种模式共用字体、布局、圆角尺度与业务行为。切换只改变材质和动效，避免控件尺寸变化、页面跳动或阅读位置改变。

当前星光按钮增加明确的当前模式说明；手机端通过不要求登录的阅读偏好入口选择模式，不再依靠隐藏按钮，也不挤占 GitHub 和个人中心的位置。兼容渲染与用户选择分别记录，避免把“渲染能力受限”误显示成完整效果。

## 6. 调整幅度：先建立候选，再逐步收敛

### 6.1 主要区域的首轮搜索范围

以下 α 均为对应底色的**不透明度**：数值越低，越能看见背后的内容。它不等于组件 opacity，更不等于最终文字区域的总不透明度。

| 参数或区域 | 当前参考 | 液态模式首轮搜索范围 | 简化模式起始范围 |
| --- | --- | --- | --- |
| 导航大面底色 α | 0.76 → 0.50 | 0.12–0.30 | 0.72–0.88 |
| 导航局部读字衬底 | 搜索框约 0.50 | 0.65–0.78，按最不利背景验证 | 0.82–0.94 |
| 卡片外层 α | 0.82 → 0.61 | 0.22–0.48 | 0.80–0.90 |
| 卡片内侧读字衬底 α | 未单独分层 | 0.62–0.76，与外层合成后验证 | 按需设置，避免无意义叠层 |
| 首屏深色大面 α | 0.78 → 0.42 | 0.30–0.50；标题下另设局部渐变 | 0.65–0.78 |
| 正文、编辑和消息底板 α | 约 0.95 | 0.94–0.98 | 0.94–0.98 |
| 全局背景较厚的浅色蒙层 | 下部接近 0.94 | 先试 0.45–0.65，两种模式保持一致 | 与液态模式一致 |
| 卡片外缘可见宽度 | 主要是 1px 边框 | 6–12px 透明过渡区域 | 固定细边框 |
| 折射影响带 | 库内置分布 | 先以边缘约 4–10px 的视觉区域校准，再随大小调整 | 无复杂折射 |
| 亮边 | 多层亮暗边叠加 | 约 0.8–1.2px 主亮边，单侧更强，另一侧柔和 | 较低对比度的均匀边框 |
| 鼠标高光范围 | 无跟随 | 半径约 120–200px，限定在当前组件 | 无连续跟随 |
| 小控件弹性 | 0 | 先试 0.03–0.08，结果再限制到实际位移范围 | 无额外弹性 |

背景照片在不同位置的明暗变化很大，透明度必须和局部读字底色一起确定。不能仅根据一张蓝天背景截图决定整站参数。

例如，两层都使用白色时，外层 α=0.34、内侧衬底 α=0.68，内侧叠加后的白色不透明度约为 `0.34 + (1 - 0.34) × 0.68 = 0.789`。这样外围仍能明显透景，中央的文字区域有较厚底色；实际对比度仍以最终背景合成为准。

### 6.2 三组首轮候选

这三组用于确定视觉方向，是组合预设，不是单变量实验；后续再固定其他因素逐项微调。**B 是优先验证的起点，尚不是最终推荐结论。**

| 参数 | A：清透但克制 | B：明显、均衡 | C：强调液态感 |
| --- | --- | --- | --- |
| 导航大面 α | 0.30 | 0.20 | 0.12 |
| 导航实际背景模糊 | 10px | 8px | 6px |
| displacementScale | 48 | 64 | 80 |
| saturation | 120 | 135 | 145 |
| aberrationIntensity | 0.4 | 0.8 | 1.0 |
| 卡片外层 α | 0.48 | 0.34 | 0.22 |
| 卡片内侧读字衬底 α | 0.74 | 0.68 | 0.62 |
| 小控件 elasticity | 0.03 | 0.05 | 0.08 |
| 鼠标高光半径参考 | 120px | 160px | 200px |

上述折射参数先用于导航和独立功能控件，不能原样复制给所有尺寸的卡片。卡片外围使用独立材质参数，正文不参与这组光学形变。

当前库在 overLight=false 时，实际背景模糊为 `4 + 32 × blurAmount` 像素。因此 10/8/6px 分别对应 0.1875/0.125/0.0625；不能把 blurAmount 当作 CSS 像素直接填写。displacementScale 也不直接等于人眼看到的边缘位移像素，必须看实际渲染结果。

### 6.3 收敛后的按部位分配

选出较好的主预设后，再按区域分配：

- 导航、独立主操作和当前选中标签承担主要识别度。
- 普通卡片和侧栏使用同一组透明度、亮边与阴影规则，折射强度通常低于导航；具体比例由不同尺寸测试确定。
- 弹窗外缘保留材质，表单底色更厚。
- 文章正文、编辑器和消息正文继续使用阅读底板。

避免所有区域同时使用 C，也避免为了性能把所有区域重新退回几乎相同的磨砂。

## 7. 动态效果如何控制

| 交互 | 目标 | 范围约束 |
| --- | --- | --- |
| 鼠标经过导航 | 光线方向随指针改变，边缘有明暗变化 | 导航的位置和尺寸不变 |
| 鼠标经过栏目或卡片 | 外缘和标题操作区响应，正文保持稳定 | 当前组件有反馈，整页不跟着摆动 |
| 鼠标离开 | 高光自然回到静态状态 | 约 180–240ms，不持续循环 |
| 独立按钮按下 | 短促压缩与亮度变化 | 目标缩放约 0.985–1，位移不超过约 1–2px；点击范围不缩移 |
| 标签切换 | 玻璃指示层跟随选中项 | 约 180–220ms，只移动装饰层 |
| 滚动页面 | 内容自然经过玻璃下方，边缘产生折射 | 不额外驱动正文视差，不让大面板追着滚动摆动 |
| 触屏 | 通过静态材质和点按反馈表现玻璃 | 不模拟持续鼠标跟随 |
| 减少动态效果 | 保留模式本身的透明度、边缘和布局差异 | 关闭非必要移动，标题直接完整显示 |

当前装饰层设置了 pointer-events:none，仅删除固定鼠标坐标不能保证交互生效。实施时要从真实的导航、按钮或卡片宿主接收指针事件，再把归一化位置传给装饰层。

不对整个 App 逐帧 setState；使用局部引用、CSS 变量或局部组件更新，经 requestAnimationFrame 合并事件，离开组件或页面不可见时停止。顶部导航不启用整体弹性位移。

## 8. 测试方法：四轮选择参数

### 第 0 轮：确认取样和材料结构正确

1. 在本地开发调参入口中，保存当前版本 B0 的首页、栏目、阅读、个人中心、写作与播放器截图。
2. 临时使用直线、棋盘格或高对比纹理检查实际折射；确认背景线条经过边缘时真的弯折，文字没有一起被滤镜处理。
3. 检查父级 filter、opacity、mask 与 backdrop-filter 对背景取样边界的影响，避免只折射到一层近乎纯色的父背景。MDN 对这些取样边界有明确说明。[实现依据](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter#backdrop_root)
4. 保留实际尺寸、背景、滚动位置和计算后的样式记录。检查到“有滤镜节点”不能直接写成“折射有效”。

本轮如果出现明显故障，先修正材料结构，再测试强度。

边缘影响带宽度是本轮封装需要实现的设计参数，组件库没有可直接照填的同名属性。限制折射区域时，应在滤镜输出或分离的装饰层中处理，并复核遮罩没有截断背景取样。

### 第 1 轮：比较 A / B / C，确定方向

在现有 5175 服务的开发调参入口中切换预设，不重启服务。入口仅在开发环境启用，普通访客页面不出现调参面板。

统一条件：同一浏览器、视口、缩放比例、系统动效偏好、页面内容和滚动位置；完成字体与图片加载后取样；静态截图时把鼠标移出组件，避免悬停状态干扰。

每个预设检查四个状态：

- **静止 5 秒：** 不操作鼠标，能否辨认透明材质、边缘厚度和两种模式的区别。
- **移动鼠标：** 导航、首屏按钮和栏目操作区的高光是否清楚、自然；文字是否稳定。
- **滚动约一屏：** 导航经过蓝天、雪山、深色首屏和浅色内容时，是否都能成立。
- **阅读 60–90 秒：** 阅读同一篇文章、查找一个栏目、打开评论，记录视觉疲劳与操作错误。

同时观察首屏整体，不能只放大边角后决定哪一组最好。先淘汰辨识度不足、对比度不够、彩边明显或灰框过厚的预设。

### 第 2 轮：围绕较好的一组逐项微调

固定其余参数，分别比较三档。若 B 胜出，第一轮微调可采用：

| 微调项 | 三个候选值 | 主要观察 |
| --- | --- | --- |
| 导航大面 α | 0.15 / 0.20 / 0.25 | 通透感与文字承托是否平衡 |
| 实际模糊 | 6 / 8 / 10px | 背景细节是否还能被看见，文字是否被背景干扰 |
| displacementScale | 56 / 64 / 72 | 边缘是否有厚度，是否出现拉扯或脏边 |
| 色散 | 0.5 / 0.8 / 1.0 | 是否增加真实感，是否出现显眼的彩色轮廓 |
| 卡片外层 α | 0.28 / 0.34 / 0.40 | 一眼能否看出卡片外围材质变化 |
| 卡片读字衬底 α | 0.64 / 0.68 / 0.72 | 摘要和时间是否易读 |
| 小控件 elasticity | 0.03 / 0.05 / 0.07 | 回应是否自然，是否影响点击与阅读 |

依次选择通过阅读检查、且观感更好的一档。单个参数缩小区间后，再把最终组合放回整页复核，避免局部最优破坏整体。

### 第 3 轮：跨页面、设备与持续阅读复核

- 使用选出的参数检查所有第 4 节列出的区域，以及空、加载、失败、禁用和选中状态。
- 覆盖 1440、1024、768、390、360、320px，检查普通与高像素密度环境；记录实际测试条件。
- 分别比较雪山亮部、暗部、图片封面与较密集的文字背景，不能只测蓝天。
- 在参考设备上阅读约 3 分钟；出现疲劳、注意力被反光吸引或正文不清楚，就降低对应区域强度，不直接削弱整站。
- 完整液态、兼容液态、简化玻璃与减少动态效果分别记录，不把模拟结果写成实体设备实测。

## 9. 评分、通过门槛与最终决定

### 9.1 评分用于比较，不替代硬性检查

| 项目 | 权重 | 关注点 |
| --- | --- | --- |
| 材质辨识度 | 30% | 静止也能看出差异，滚动和交互能感到厚度与光线 |
| 美感与一致性 | 25% | 轻盈、干净、与雪山背景协调，没有塑料灰框和显眼彩边 |
| 阅读与操作 | 30% | 文字易读、输入稳定、按钮可预测、持续阅读不累 |
| 性能与兼容 | 15% | 滚动、输入、点击流畅，降级外观仍完整 |

每项使用 1–5 分。综合分接近时，优先选择阅读评分更高、复杂度更低的一组；最终还需用户在实际博客中确认观感。

### 9.2 必须通过的门槛

- 普通文字对比度至少 4.5:1，大字号文字至少 3:1；半透明区域按合成后的背景验证，不能只计算纯色变量。[对比度依据](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 文字、代码和输入内容没有折射、重影或持续位移；文字选择、光标与输入法正常。
- 模式切换后，布局、点击目标、滚动位置和表单内容保持稳定。
- 桌面静态首页能在导航、首屏、栏目/侧栏三个区域观察到材质区别；手机首屏先看到导航与首屏面板的区别，向下滚动后能辨认栏目材质。阅读页能在导航和功能控件看到区别。
- 鼠标反馈不是只有按钮原有的上浮；至少能观察到光线方向变化，完整效果环境中能验证真实边缘折射。
- 减少动态效果时关闭非必要移动，仍能区分两套材质。W3C 的交互动效指南支持提供关闭非必要动画的方法。[动效依据](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)
- 登录、搜索、写作、图片上传、配乐、通知与私信的核心操作不受装饰层遮挡。

可邀请用户自行选取少量读者参与 5 秒对比，随机标记 X/Y，记录能否辨认材质区别及偏好。例如 5 人中至少 4 人能辨认差异可作为设计筛选目标，但不能视为统计学证明；只有用户参与时如实记录 n=1，不虚构读者测试结论。

### 9.3 性能验证与退让顺序

在同一参考设备上，每组重复三次相同的滚动和指针路径，记录 rAF 帧间隔、明显停顿及浏览器性能轨迹。rAF 只能帮助观察帧节奏，不能单独证明 GPU 渲染成本。

若参考显示设备为 60Hz，可先把 p95 帧间隔约 20ms、滚动掉帧比例不超过约 5% 作为调参目标；这些是项目测试预算，需根据实际基线校正，不是已经取得的结果。

第一版将同屏复杂折射层上限设为约 3 个：导航、当前交互控件、当前浮层各最多一个。普通卡片使用 CSS 材质和局部高光，离屏元素不持续更新。

性能不足时依次减少同时激活的折射层、缩小滤镜影响区、降低高光更新频率或使用兼容渲染。保留已经建立的全站透明度和层次差异，避免降级后两种模式又变得几乎一样。

## 10. 模式、设备与兼容策略

当前 enabled 同时受鼠标能力、浏览器与减少动态效果影响，实施时拆分为用户选择、光学能力和动效偏好三个独立判断。

| 环境 | 液态模式表现 | 动态安排 |
| --- | --- | --- |
| 实测支持复杂折射的桌面 Chromium | 完整材质、边缘折射、方向高光 | 精细指针下启用局部交互 |
| Safari / Firefox 等兼容环境 | 相同的通透度、读字衬底、亮边与阴影；使用兼容材质 | 保留能够可靠呈现的反馈，不宣称有未实测的真实折射 |
| 触屏与小屏 | 以清楚的静态材质区别为基础，按设备实测决定光学档位 | 关闭鼠标跟随，保留合适的点按状态 |
| 减少动态效果 | 保留所选材质的静态外观 | 关闭非必要移动与形变 |
| 用户选择简化 | 全站使用较厚、稳定的磨砂材质 | 不启用复杂光学动画 |

组件库官方仍注明 Safari 和 Firefox 对位移效果支持有限，因此兼容液态必须单独验收，不能仅靠 CSS.supports 的语法检测判断效果完整。[组件兼容说明](https://github.com/rdev/liquid-glass-react#-features)

## 11. 实施结构与工作顺序

### 11.1 拟调整的代码

| 位置 | 工作 |
| --- | --- |
| `frontend/src/hooks/useGlassCapabilities.tsx` | 拆分选择、兼容能力与减少动态效果，保留选择持久化 |
| `frontend/src/components/glass/GlassBackdrop.tsx` | 支持区域强度与宿主指针输入，避免全局固定坐标和层层重复折射 |
| `frontend/src/components/glass/` | 按需要补充材料外壳与操作控件适配，保留原生交互语义 |
| `frontend/src/styles/glass.css` | 用模式变量覆盖全站材料；统一外层、衬底、边缘和阴影，整理重复覆盖规则 |
| `frontend/src/styles/media.css` | 协调配乐、弹窗、编辑标签与模式变量，不覆盖现有保存按钮和提示位置调整 |
| `frontend/src/App.tsx` | 给现有区域接入材料角色和宿主引用，保持现有业务流程 |
| `frontend/src/components/ArticleContent.tsx` 等实际媒体组件 | 仅在需要时适配播放器外壳与控制层，保持播放和授权逻辑 |
| `frontend/src/vendor/liquid-glass/` | 仅在背景取样或边缘实现需要修复时修改，继续记录上游来源与差异 |

继续使用现有 React 版本和 MIT 来源的组件实现，不为这一轮视觉调整更换整体技术栈。复杂 shader 模式不作为默认方向。

### 11.2 按可检查结果推进

| 顺序 | 工作 | 交付节点 |

## 12. 验收交付物与完成定义

实施后的交付物：

1. 具有明显模式区别的完整界面，覆盖第 4 节的页面与状态。
2. 固定下来的分区域参数表，记录最终值及选择原因。
3. B0、A/B/C 候选、最终版的对照截图，以及鼠标、滚动、点按效果的短录屏。
4. 调参记录：预设、区域、设备、背景、实际参数、阅读问题、性能观察、评分、保留或淘汰原因。
5. 完整、兼容、简化和减少动态效果的验收结果；未测试的设备与浏览器如实标注。
6. 原有功能回归和生产构建结果。

调参记录建议放在本地 `.dist/liquid-glass-v2/`，最终结论整理为仓库文档；调参面板只在开发环境使用，正常访客界面不暴露实现参数。

本轮完成的标志：读者打开和浏览页面时能看出统一的玻璃材质，交互时能感到光线与厚度变化，切换简化模式后能立即辨认差异；正文仍清楚，操作仍稳定，效果没有依靠说明文字来证明自己存在。

本方案中的数值尚未经过第二轮实现和 A/B/C 实测。本次文档提交不包含工作区中已有的写作界面等未提交修改。
